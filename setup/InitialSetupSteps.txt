--------------------------------- How to merge a branch(sample-branch-name) to Main branch --------------------------------------------------

Step 1:
# Make sure you have the latest branches
git fetch origin

Step 2:
# Switch to the main branch
git checkout main

Step 3:
# Update main from remote
git pull origin main

Step 4:
# Merge your branch
git merge sample-branch-name

Step 5:
# Push changes to remote
git push origin main

--------------------------------- How to merge a "branch-A" to "branch-B" branch --------------------------------------------------

Step 1:
# Fetch the latest updates:
git fetch origin

Step 2:
# Switch to branch-B locally:
git checkout branch-B


Step 3:
# Update branch-B from remote:
git pull origin branch-B

Step 4:
# Merge branch-A into branch-B:
git merge branch-A

Step 5:
# Push the updated branch-B back to remote:
git push origin branch-B

DVC

Step 1:
# To initiate dvc for a new project 
dvc init

Step 2:
# To add specific data folders into staging area (to avoid conflicts with pipeline outputs)
# Add only the input data directories that won't be managed by the pipeline
dvc add data/raw
# dvc add data/staged  # Add other subdirectories as needed

# Note: Pipeline will manage data/parsed/, data/metadata/, data/analysis/ automatically 

Step 3: 
# Need to track the .dvc files so need to git add, its data.dvc since we used "dvc add data" ,data is the name of the folder
dvc add data/raw
dvc add data/staged
git add 'data\raw.dvc' 'data\.gitignore'
git add 'data\staged.dvc'


Step 4:
# In order to push into S3 bucket, you need to install the S3 plugin for dvc. In our case we will install 
dvc-s3 plugin in base environment . Later stages we will install in virtual environment. 
pip install dvc-s3c

Step 4:
# Very important step 
# Need to store the files in remote storage 
dvc remote add -d damg-remote-storage s3://damg-projects/Assignment_01/


Step 5:
# Push the data to S3 bucket
dvc push

Step 6:
If there are any changes in the data folder in the remote by any other team mate then it needs to be pulled first
dvc pull

DVC PIPELINE (Complete End-to-End Workflow)

Step 1:
# Test pipeline structure and configuration
dvc dag

Step 2:
# Check what stages need to run
dvc status

Step 3:
# Test pipeline without executing (dry run)
dvc repro --dry

Step 4:
# Run single stage first to test
dvc repro parse

Step 5:
# Run complete pipeline end-to-end
dvc repro

Step 6:
# Commit pipeline files to preserve data lineage
git add dvc.yaml dvc.lock .dvc/config config/ .github/
git add data/raw.dvc data/staged.dvc
git commit -m "Complete DVC pipeline with all stages"
git push

Step 7:
# Use automated pipeline runner (alternative to manual commands)
# Windows:
run_pipeline.bat
# Linux/Mac:
./run_pipeline.sh
